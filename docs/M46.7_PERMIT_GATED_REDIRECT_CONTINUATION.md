# M46.7 — Permit-Gated Redirect Continuation

M46.7 converts a response-backed, previously unfollowed HTTP redirect into one immutable continuation candidate. Candidate creation is offline and cannot authorize network I/O.

Execution remains delegated to the existing bounded field-assessment wrapper, which must obtain a fresh live program pre-flight and a fresh execution permit for the exact redirect target. Redirects are never followed automatically.

Fail-closed conditions include invalid provenance hash, session/provenance mismatch, missing response evidence binding, non-3xx source response, already-followed redirect, missing `requires_new_permit`, non-HTTPS redirect, or redirect outside the source compiled scope.

The execution ceiling remains one GET, one fresh permit, no state change, no brute force, and no broad scanning. A further redirect requires another operator-reviewed continuation cycle.

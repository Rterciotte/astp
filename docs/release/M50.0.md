# M50.0 — ASTP 1.0 Stable

M50.0 promotes the qualified ASTP 1.0 release-candidate line to stable `1.0.0`.

## Qualification baseline

The stable release is based on the qualified `v1.0.0rc2` line.

The release-candidate campaign validated:

- clean clone of the published RC tag;
- fresh Python 3.12 virtual environment installation;
- public CLI walkthrough;
- full regression and repository validation;
- deterministic M48.6 CTF acceptance;
- real M48.0 Bug Bounty stored assessment chain;
- permit lifecycle and replay resistance;
- evidence, manifest, audit and bundle integrity;
- expected-input CLI failure handling;
- internal consistency of release acceptance reports;
- real report generation from stored authorized evidence.

## Stable promotion

M50.0 changes release metadata and documentation only:

- version: `1.0.0`;
- milestone: `M50.0`;
- channel: `stable`.

It introduces no new target-execution capability.

## Security invariants

Stable preserves the qualified RC safety model:

- authorization precedes target execution;
- discovery never grants execution authority;
- every target network action requires a fresh exact permit;
- consumed permits cannot be replayed;
- offline analysis does not retrieve discovered targets;
- evidence integrity is verified before downstream use;
- findings cannot exceed their evidence-backed proof state;
- CTF automation remains bounded by challenge rules and ASTP policy.

## Release qualification network behavior

The stable-release qualification itself does not perform assessment-target network requests.

Previously collected authorized evidence may be verified, analyzed and reported without replaying the original target request.

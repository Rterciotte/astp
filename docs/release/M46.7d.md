# M46.7d — Response Body Artifact Persistence

M46.7d closes the gap where the HTTP observation worker captured and hashed the full bounded response body but retained only a 4096-character preview in the evidence JSON.

## Behavior

- Raw bounded body persistence is **opt-in** with `--persist-body`.
- Default behavior remains unchanged (`--no-persist-body`).
- The persisted artifact is a sibling of the evidence JSON named `<evidence-stem>.body.bin`.
- Writes are atomic and fsynced before replacement.
- `HttpObservationEvidence` records a `body_artifact` reference containing path, SHA-256, byte size, and inherited sensitivity.
- The body artifact is registered in the evidence manifest as `http.observation.body` and remains bound to the same evidence ID, permit ID, and action ID.
- The normal observation evidence remains separately registered as `http.observation`.
- HEAD observations never create a body artifact.
- The bounded capture limit remains authoritative; this does not increase network scope or request count.

## Security posture

Persisting raw bodies can retain data that is intentionally absent from the redacted preview. For that reason persistence is not enabled by default. Callers must choose it only when retaining the response is appropriate for the engagement and sensitivity label.

M46.7d changes evidence retention only. It issues no permit and performs no network action by itself.

## Validation

```powershell
.\scripts\validate.ps1
```

Before any field request, obtain current program authorization and a fresh permit as usual. For a deliberately retained bounded response, add `--persist-body` to `observe-http`. Afterward verify that `body_artifact.sha256 == body_sha256`, the file size equals `body_bytes_captured`, and `verify-evidence-manifest` succeeds.

# M46.7a — Assessment Autonomy Hardening

This patch closes field-test gaps found during the Smart Fit assessment without weakening the policy-first invariant.

## Changes

- Adds a bounded `ProgramOperationalLease` (maximum 30 minutes) derived only from an ONLINE attestation while it is still fresh. The lease is bound to program ID, policy/source-content hash, attestation ID/timestamp, assessment ID, and preflight report hash.
- A stale source attestation may only be used when paired with a still-valid, integrity-bound assessment lease. A fresh execution permit is still mandatory for every request.
- `plan-observations` and `broker-permit` accept `--program-status-lease`.
- Planner and permit broker preserve the concrete authorization blocker instead of collapsing all failures into a generic `insufficient_context` message.
- Prioritization favors JavaScript/API surfaces and penalizes low-value static assets such as favicons and stylesheets.
- Crawl frontier excludes out-of-scope discovered targets rather than marking them `ready`.
- New field assessments persist an immutable operational lease alongside the preparation artifact.

## Non-goals

The lease does not refresh BugHunt automatically, does not extend beyond 30 minutes, does not bypass policy drift, scope, semantic exclusions, rate limits, state-change approval, intrusive denial, or permit replay protection. A later durable observer/refresh milestone can replace this bounded bridge.

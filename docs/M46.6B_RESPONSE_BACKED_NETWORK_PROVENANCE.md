# M46.6b — Response-backed network provenance

M46.6b fixes a reporting-integrity contradiction discovered during the first successful bounded Smart Fit field observation.

The executor had immutable evidence proving an HTTP 301 response, while the later offline `assess` phase still emitted `network_execution_performed: false`. The offline analysis phase itself correctly performs no network I/O, but that fact must not erase network execution that already occurred earlier in the same field assessment.

The field wrapper now binds the successful `execution-status-<hash>.json` to integrity-valid response evidence and writes an immutable `network-provenance-<hash>.json`. Only after that binding succeeds does it update the structured result/report to state `HTTP_RESPONSE_OBSERVED` and `network_execution_performed: true`.

The normal offline assessment API keeps its conservative default (`false`) for workflows that have no separately proven execution provenance.

Redirects remain unfollowed unless separately authorized and permitted. The provenance section records when a redirect requires a new permit.
